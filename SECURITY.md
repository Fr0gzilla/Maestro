# Signaler une faille

Cette revue décrit la conception de Maestro et publie des extraits de code. Si vous pensez avoir trouvé une faille —
dans un extrait, ou dans la conception décrite — merci de la signaler **en privé** : onglet **Security** de ce dépôt,
puis **Report a vulnerability**. Jamais par un ticket ou une discussion publics.

**Ce qui aide** : le fichier ou le chapitre concerné, le scénario d'attaque, l'impact supposé, et ce qui vous ferait
dire que la faille est fermée.

**Ce qui suit** : un accusé de réception sous sept jours. Si la faille touche le système en service, elle est corrigée,
puis la revue est mise à jour — avec votre nom dans les remerciements, si vous le souhaitez.

**Hors périmètre** : l'ingénierie sociale, les tests contre une infrastructure qui n'est pas décrite ici, et les
attaques contre GitHub lui-même.
