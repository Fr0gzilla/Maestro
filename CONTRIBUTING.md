# Donner un conseil

Cette revue est publique pour être discutée. Un avis d'expert, une critique argumentée, une piste à laquelle personne
n'a encore pensé ici, un retour d'expérience sur un système comparable : tout est bienvenu.

## Où écrire

| Vous avez… | Où |
|---|---|
| un conseil, une idée, une critique | les **Discussions**, catégorie *Ideas* (formulaire « Un conseil ») |
| une question sur un choix, un chiffre, un diagramme | les **Discussions**, catégorie *Q&A* |
| repéré une erreur dans la revue (chiffre, lien, diagramme, coquille) | un **ticket** « Une erreur dans la revue » |
| trouvé une faille de sécurité | **en privé**, jamais en public : voir [SECURITY.md](SECURITY.md) |

## Là où un regard extérieur serait le plus utile

- **L'isolation des agents** : le conteneur, les sorties filtrées, et les [risques connus](docs/05-securite.md#ce-qui-reste--risques-connus)
  qui restent ouverts.
- **La sobriété** : réduire le contexte relu sans perdre en qualité ([L'économie de tokens](docs/06-economie-tokens.md)).
- **La robustesse du protocole** face aux réponses de modèles hors format ([Les agents](docs/04-agents.md)).
- **L'exploitation** d'un système qui travaille seul la nuit : ce qu'il faudrait surveiller de plus, ou autrement.

## Les règles des échanges

- **Bienveillance et précision** : on discute des choix, pas des personnes.
- **Des faits** : une mesure, une expérience ou une source valent mieux qu'une opinion.
- **Rien de sensible en public** : ni donnée personnelle, ni secret, ni code d'attaque fonctionnel.

## Les contributions

Le code complet de Maestro est privé. Les *pull requests* sur ce dépôt portent donc sur la revue elle-même :
une coquille, un lien cassé, une formulation à clarifier.
